# Gaps to resolve before calling the helper useful

Open product/qualification gaps, refreshed for the reviewed `0.4.0.dev37` source. [Current status](current-status.md) records source, validation and delivery separately; [the workbench guide](visual-workbench.md) describes implemented controls. Explicit session folder connection, job-first failure/source workflows, actual shared preparation activity, draft saving/opt-out/clear and selected retry/reconnect repairs already exist. The gaps below are remaining limits, not a claim that these controls are missing.

| Gap | Why it matters | Test or decision |
| --- | --- | --- |
| When to skip the helper | A small request may cost more in tool descriptions, calls and follow-up evidence than a direct host answer. | Include trivial tasks and a direct-host baseline. A future router should choose by measured benefit, with a cheap deterministic path and no hidden model swarm. |
| Retrieval can lose evidence before summarization | Up to two primary windows per file, within four primary records plus up to six controlling-context records (ten total), may omit a distant branch or dependency. Bytes and other limits can reduce that set. | Include far-apart contradictory spans and cross-file cases. The [source-span development audit](source-span-development-2026-11-11.md) measures exposed synthetic spans separately from file hits. It is not unseen accuracy qualification; a complete-sounding summary cannot repair absent evidence. |
| Shared mistakes across models | A host may repeat a plausible worker error instead of independently assessing the source. | Inject an incorrect note in a controlled trial; compare host conclusions with and without it. Neither the worker nor the same task's host should supply the reference answer. |
| Benchmark answer leakage | Tuning on exposed questions can improve the score without improving the product. | Keep grading keys outside fixture roots and packets. Treat this task lab as development material. Create an unseen, separately reviewed set before promotion; no held-out result is claimed now. |
| Cold starts and model changes | A warmed, idle GPU is an incomplete picture of day-to-day use. | Record cold/warm load time, memory headroom, concurrent workloads, model swaps and deadline failures. A larger local model must justify its loading and inference costs. |
| Settings are part of the model | Quantization, chat template, thinking mode and output budget can change results. | Record each model/profile as a distinct candidate. Change one dimension at a time and retain the losing runs. Existing fixed worker settings are a baseline, not a tuned recommendation. |
| Stale context and shared files | Captured source can change while another task or user edits the checkout. | Existing hashes and earlier-capture labels retain identity. Failed-run JSON stays saveable during failed/obsolete rechecks, without newer edits. A fresh accepted check is still needed for current evidence; durable cross-session recovery remains planned. See [capture recovery](captured-report-recovery-2026-11-11.md). |
| What actually reaches the cloud | Filename filters do not find every secret embedded inside ordinary source or logs. | Before a cloud adapter is promoted, define an outbound-content policy and tests for embedded secrets. Redactions must be disclosed; redacted material cannot be labeled byte-exact. No cloud adapter is implemented now. |
| Quota versus token estimates | A shorter brief does not establish fewer subscription-limit events or lower total cost. | Use actual usage where exposed; keep local estimates, cached input, output and unobservable quota behavior distinct. Include failed runs and retries. |
| Cost of abstaining too often | Refusing every task can avoid false statements while leaving all work to the host. | Score useful completed jobs and recovery questions alongside unsupported claims and misses. The helper must reduce work without bluffing. |
| Upgrade regressions | A model tag or dependency update can alter working behavior. | Pin identities before promotion, rerun the qualification set on change, retain a last-qualified profile and document rollback. Reported digest and pipeline enforcement are implemented; a complete authenticated promotion lifecycle remains pending. |
| User effort | A helper that repeatedly asks routine setup questions can increase work. | Compact workflows, contextual connection, optional run details and actual activity are implemented with scoped checks. Representative task studies and full accessibility still need qualification; automatic setup/calibration and profile dashboards remain planned. See [workbench review](workbench-usability-2026-11-11.md). |

The first product milestone remains a measured, evidence-preserving local Ollama handoff through a real host. The task lab supplies development inputs and mechanical evidence checks; it does not replace that end-to-end qualification.

[Optional embedding reranking](embedding-rerank-2026-11-07.md) is implemented for explicit CLI/benchmark use and remains off by default. It reorders permitted candidates rather than reading arbitrary new source. Its existence does not close retrieval coverage, model accuracy or end-to-end benefit gates. Automatic calibration, persisted per-PC profiles, connected cloud Send and richer visual dashboards remain proposals.
