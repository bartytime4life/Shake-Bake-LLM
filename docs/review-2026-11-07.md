# Review pass: errors, logic, UI and UX

Status: a review of everything stacked above `main` on November 7, 2026, done
in three parts: the mechanical suites, a correctness-focused code review of
the diff, and a hands-on pass through the running workbench in headless local
Chrome with this repository itself as a project. Fixes landed in `0.4.0.dev19`
and are recorded as BUG-021. No cloud host or chat model ran; the measurements
are the collector's own.

## Code review: ten findings, all fixed

1. **GUI and MCP path rejected any job with controlling-context windows
   (severe).** `HelperSession` still validated runner results against the old
   four-record cap, so a preparation with five or more exact records ended in
   `invalid_runner_result` with no evidence, from `dev10` to `dev18`, while the
   CLI brief worked. The demo project adds no context windows, so the
   real-Chrome suites never saw it. Now bounded by `collector.MAX_FILES`.
2. **`fetch_evidence` accepted only `E1` to `E4`**, so the host could never
   retrieve a context excerpt it was told about. Now any id up to the packet's
   length, at most ten; the MCP docstring says so.
3. **Embed batch size could exceed the transport cap** for higher-dimension
   models (eight vectors of 4,096 floats is about 420 KB against a 256 KB cap),
   so such models would always have fallen back silently. While this review
   was in progress a separate fix landed on `main` that keeps the fixed batch
   of eight but fails closed with the refusal visibly recorded and tested; the
   merge keeps that behavior rather than the adaptive batch sizing drafted
   here. The keep-alive between batches from the trial follow-up is retained.
4. **The recall adapter counted context windows as primary** when fewer than
   four primary windows existed. The fix that landed on `main` in parallel
   derives primaries from the controlling-context ids and reports
   `primary_excerpts` and `controlling_context_excerpts`; the merge keeps it.
   The thirteen external cases all had four primaries, so their published
   figures stand; the self-commit figures could have been affected in cases
   with few matching files.
5. **The five-second scan deadline bounds only the walk.** Scoring, the context
   pass, the line index and an optional rerank (own 20-second deadline) run
   after it. The limit's comment now says so instead of claiming a hard stop.
6. **A refused rerank call inherited the previous call's record** (dimensions,
   calls, elapsed time, usage) because the scorer's record persisted across
   calls. It is now reset at the start of every call.
7. **Rerank telemetry was sent to the local worker** inside its collection
   record, spending its byte budget on similarity lists it cannot use. The
   worker now receives only model, pool, candidate count, whether the order
   changed and any refusal code; the receipt keeps the full record.
8. **`rerank_pool_budget` was reported even when the rerank refused**, implying
   windows were excluded from an ordering that never happened. It is now set
   only after a successful rerank.
9. **Test-file detection matched `contests.py`, `testament.py` and
   `spectrum.py`**, so ordinary modules could be labeled the test evidence.
   The stem must now be `test`, `tests` or `spec`, or carry one as a `_` or
   `.` prefix or suffix, or sit in a test directory.
10. **Prose files registered English words as definitions** ("let the server
    start" indexed `the`), and generic or ambiguous names (`name`, `files`,
    `context`, anything defined in more than two places) were followed as
    controlling context. Markdown and text files no longer feed the definition
    index (they still count as places where a name is used or tested), and
    generic or ambiguous names are skipped.

One further fix came from the measurements after these changes: a request
that writes `MobileNetV3` did not match the path `mobilenet_v3.py`, so path
matching now also compares with separators removed.

## UI and UX pass in headless Chrome

The workbench was started on a fresh state directory with the starter demo and
this repository as projects, driven with Playwright and local Chrome 157, and
checked at desktop and phone widths.

- A real-repository request round-tripped in about 600 ms and produced nine
  excerpts, five of them labeled as controlling context, with the file map and
  the matched-line index in the copied brief, the size line reading about
  16.6 KB and 4,200 estimated tokens. No console errors, page errors or failed
  requests. The demo request still produced its two excerpts.
- Every `#` or `##` line in the copied brief outside a fence is one of the
  brief's own headings; comment lines from Python excerpts stay inside their
  fences, as designed.
- Phone width: no page-level horizontal overflow; long code lines scroll inside
  their own blocks. Tab order from the request reaches Prepare, Copy and the
  two assistant links in sequence.
- Copy worked; the manual-copy fallback stayed closed because the browser
  accepted the write.
- **One UX problem found and fixed.** The gaps panel opened on a complete scan
  with the warning "Collection reached these limits" followed by six internal
  cap names (`context_budget`, `context_map_budget`, `selection_budget`, …).
  Those are routine selection caps, not a scan that stopped early. The page,
  the copied brief and the CLI brief now separate the two: time, file, entry
  and depth budgets are reported as "scan stopped early" with a warning;
  window, context, map, index and rerank caps are reported quietly as
  "selection caps applied"; and routine exclusions (unsupported extensions,
  excluded directories, low-signal matches, binary and non-UTF-8 files) stay in
  the receipt rather than the warning. On this repository the panel now shows
  only the one notable exclusion, a denied path.
- Context reasons on the source cards sit inside the collapsed "View source
  excerpts" section, so they are visible only after expanding it; the copied
  brief carries them regardless. Left as is.

## Checks after the fixes

236 Python tests pass after merging with the parallel `main` changes, three of
them new here: the helper runs a real child on a project that yields more than
four records and fetches the last one; test paths and prose definitions are
classified narrowly; generic and ambiguous names are not followed as context.
The keep-alive sequence and the blend fields are asserted in the rerank suite
that landed on `main`. The 18 clipboard cases, the
frontend smoke and all three real-Chrome suites (33 workbench, 5 clipboard,
14 readiness) pass. Task Lab keeps 10/10; the four fixtures are unchanged
(6/6, 6/7 plus one mapped, 6/6, 5/6 plus one mapped); the self-commit figures
are unchanged; the thirteen external cases are back at 9/13 reached at the
default and 10/13 at the ceiling after the path-match fix (the first pass of
the fixes had dropped keras to the map's thirteenth slot).

## What this does not establish

- That no further defect exists; the review covered the stacked diff and one
  real repository through the workbench, not the whole program.
- Anything about answer quality or host turns; no model ran.
- The visual rendering a person sees; the checks read the DOM and the copied
  text and took screenshots that were not reviewed by a person.
